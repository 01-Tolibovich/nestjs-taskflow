# 0.1 — Как устроен HTTP-запрос

## Главное
- HTTP — текстовый протокол «запрос → ответ» поверх TCP. **Stateless**: сервер не помнит прошлые запросы, поэтому, например, токен шлётся в каждом запросе.
- **Запрос**: стартовая строка (`МЕТОД /путь HTTP/1.1`) → заголовки → пустая строка → тело (не всегда).
- **Ответ**: статус-строка (`HTTP/1.1 201 Created`) → заголовки → пустая строка → тело.

## Методы
| Метод | Смысл | Безопасный | Идемпотентный |
|---|---|---|---|
| GET | получить | ✅ | ✅ |
| POST | создать | ❌ | ❌ |
| PUT | заменить целиком | ❌ | ✅ |
| PATCH | изменить частично | ❌ | зависит от патча |
| DELETE | удалить | ❌ | ✅ |

- **Безопасный** — ничего не меняет на сервере.
- **Идемпотентный** — N одинаковых запросов дают тот же итог, что и один.

## Статус-коды
`2xx` успех · `3xx` перенаправление · `4xx` ошибка клиента · `5xx` ошибка сервера.

200 OK · 201 Created · 204 No Content · 400 Bad Request · 401 Unauthorized («кто ты?») · 403 Forbidden («знаю кто ты, но нельзя») · 404 Not Found · 409 Conflict · 500 Internal Server Error.

## Заголовки
- `Content-Type` — формат тела (`application/json`).
- `Content-Length` — размер тела в байтах.
- `Authorization` — учётные данные (`Bearer <token>`).

## Из примера на `node:http`
- Роутинг вручную: `if` по `req.method` и `req.url` — эту работу потом делают Express и Nest.
- Статус и заголовки выставляются через `res.writeHead`, тело — `res.end`.
- Тело запроса — **поток**, его надо собрать из кусков.
